## Important findings

1. **Startup can accept a revision that makes the next persisted save unreadable.** `src/core/store.ts:107` accepts `9999-12-31T23:59:59.998Z` because one later millisecond exists. `src/core/store.ts:151` prefers it over a normal replica. The first successful action persists `.999Z`, then `src/core/store.ts:14` throws on every later action, including import and reset. Reload rejects both terminal copies if the write reached both replicas, dropping the user's progress from the active snapshot. `tests/store.test.ts:210` covers terminal input only. Normalize or reject dangerous startup clocks before they are eligible to win replica selection, and make sure the allocator can never persist a revision the loader rejects. Test initialization from `.998Z`, several writes, reload and recovery with both storage copies. Preserve ordinary historical timestamp strings and replica ordering.
2. **Unlocked chapter navigation stops working for a reader.** `src/core/store.ts:260` makes `setChapter` a no-op as required for a read-only store, but `src/main.ts:150` still uses it as the only way to visit an unlocked chapter. The journey rerenders the old chapter because `src/main.ts:72` reads the saved chapter. Use a transient chapter selection for read-only browsing, including the selected chapter's species/cards and quiz. Test an owner with two unlocked chapters, switch chapters as its reader, and verify the reader's export and both storage copies stay unchanged.
3. **Read-only quizzes grade a correct answer as wrong.** `src/core/store.ts:219` returns `{ correct: false, points: 0 }` for every denied answer. `src/main.ts:102` passes that store straight to the quiz. `src/modes/quiz.ts:42` uses `result.correct` for scoring and feedback while line 43 independently highlights the actual correct option. The learner can see the correct option highlighted, an incorrect feedback message, and a zero score simultaneously. Grade a transient attempt using the question answer while withholding rewards and avoiding “already rewarded” text, or explicitly disable attempts with a read-only explanation. Cover one known-correct answer with no snapshot mutation.
4. **Canceling the native file picker closes Settings and disposes its importer.** `src/main.ts:220` receives any bubbling `cancel` from a descendant, and the common modal listener at `src/core/ui.ts:25` closes on the same event. The file upload input can dispatch a bubbling `cancel` on dismissal. The `change` listener at `src/main.ts:221` never receives that event, so canceling a file choice dismisses Settings instead of clearing the pending selection and allowing a retry. Handle `cancel` on the file input, stop propagation, and invalidate the pending selection through `select(undefined)`. Keep dialog-targeted cancel working. Add a browser-level case that dispatches a bubbling cancel on the input during a delayed read, checks Settings remains open, then retries successfully. `tests/progress-import.test.ts:23` exercises only the controller call.
