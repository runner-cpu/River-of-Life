# Interaction enhancement evidence

## Task 1 — epoch and archive relationships (2026-11-12)

Implementation uses native TypeScript, DOM and SVG. `src/content/relationships.ts` derives the eight editorial groups and all 48 published/source-checked archives directly from chapters/species. `src/core/relationships.ts` owns range, log(1 + MYA) positioning, two calculated temporal reference sentences and immutable expansion toggles. `src/modes/relationships.ts` and `.css` render the expanded time diagram, equivalent grouped list, selected archive details and responsive layouts. Epoch ranges and archive ranges remain separate; notably cyanobacteria/stromatolites extend to the present rather than being clipped at the first chapter boundary. The interface explicitly disclaims a complete phylogeny and same-place/same-time coexistence.

`src/core/types.ts`, `src/main.ts` and `src/modes/help.ts` connect the mode, hash route, main navigation and guide. Main's existing read-only diagnostics now includes a cloned Progress snapshot so browser evidence checks full memory state, including updatedAt, without exposing mutable store references. `src/modes/specimen.ts` adds the approved optional fourth `{ readOnly: true }` argument; default callers retain progression. Observation is gated before invocation; read/collect/compare/lab handlers independently guard invocation, including synthetic clicks. Size comparison remains visible and useful. The existing modal captures the originating archive node for close/Escape focus restoration. Collapsing the selected epoch clears the detail so no stale source can be opened.

No dependencies or runtime requests were added. Progress fields, version and import/export validation remain unchanged. Relationship code/styles are bundled into existing local JS/CSS, which the production offline manifest enumerates and the content revision hashes. Personal downloads and external sources are not site-cache promises. Existing external source links, speech and AR retain their existing connectivity limits.
